# Security policy

## Report a vulnerability

Do **not** report vulnerabilities in public issues, pull requests, discussions, or support requests.
Do not post exploit details, credentials, certificate keys, or confidential data there.

Email [security@delphoslabs.com](mailto:security@delphoslabs.com) for private reports.
This is the contact published in Delphos Labs' [security.txt](https://delphoslabs.com/.well-known/security.txt).
Use its published encryption key when the report needs encrypted delivery.

When private vulnerability reporting is enabled, you can also use **Report a vulnerability** on the repository's
[GitHub security advisories page](https://github.com/Delphos-Labs/roxxy/security/advisories).
Confirm that GitHub offers a private report form before submitting details.

If the button is unavailable, use the email contact. Do not use a public issue as a fallback.
Administrators must enable private vulnerability reporting and confirm its recipients during public release setup.

## Include in a private report

Include the affected version or commit,
reproduction steps, impact, and any proposed mitigation.
Remove unrelated confidential information. Test only systems you are authorized to test.

## Security maintenance

No supported-version schedule or response deadline is currently published.
Maintainers must define security coverage before making support commitments.
